# MobilityPilot Dashboard · 郑州城市调度可视化原型

郑州大学首届 AI 智能体创新应用大赛 · 自主命题
**MobilityPilot：面向城市出行的多智能体协同决策与动态调度系统**

单文件交互原型，演示 **5 类功能智能体**（天气环境 / 态势感知 / 路径规划 / 调度派单 / 司机执行）在**郑州市主城区**接力完成一次调度派单的完整过程。**平台本身也是一个智能体**，统一管理 **8 名接入 LLM 思考、具备独立记忆与性格的司机智能体**；整体设定为**车多乘客少**，以突出平台推荐调度算法的价值。接入高德开放平台的现实数据接口，并支持导入逐车历史轨迹做时间轴回放。双击 `index.html` 即可运行。

---

## 一、五个智能体

| 编号 | 智能体 | 职责 | 关键动作 |
| --- | --- | --- | --- |
| A0 | **天气环境智能体** | 感知环境 | 调用 AMap.Weather 取郑州实时天气，换算需求影响系数（晴 ×1.00 / 小雨 ×1.20 / 暴雨 ×1.55 / 雪 ×1.38~1.56），作为环境输入修正 A1 需求与 A2 ETA |
| A1 | **态势感知智能体** | 看清城市 | 高德 POI 检索校准片区坐标，融合实时路况、车辆位置、订单流，输出区域供需缺口 |
| A2 | **路径规划智能体** | 算清路 | 调用 AMap.Driving 做真实路网规划，输出路径点、距离、ETA 与空驶成本；**无实时 GPS 时用规划路径反推车辆位置** |
| A3 | **调度派单智能体** | 派对人 | 综合评分（收益 − 成本 − 聚集惩罚）+ 车辆-订单匹配，下发派单与推荐路线 |
| A4 | **司机执行智能体** | 跑完单 | 代表司机与车辆确认接单，沿规划路线行驶、送达、结算 |

A0 作为环境输入层同时连向 A1 / A2；A1 → A2 → A3 → A4 首尾相接形成闭环，执行结果回写为区域权重与司机阈值，供下一轮 A1 / A3 使用。

### 1.1 平台智能体与 8 名司机智能体

上述 A3「调度派单」在本原型中进一步具象为**平台智能体**，A4「司机执行」则展开为 8 个彼此独立的司机 Agent，构成真正的多智能体交互：

| 层 | 实现 |
| --- | --- |
| **平台智能体** | 每 3 个仿真步生成一批订单，平峰 2 单、高峰 3 单。平台优先处理积压订单，按接驾距离、区域偏好、合规倾向与近期接受率给空闲司机排序。每单每批最多邀约 3 位新司机，下一批继续尝试。等满 6 批或全车队均已拒绝时关闭订单 |
| **司机执行与反馈** | 接单后车辆依次接驾、载客、送达，送达时写入收入和完成单数。每次响应更新近期接受率，供后续派单使用 |
| **司机 LLM 思考** | 每个司机收到派单后运行**链式推理**（态势评估 → 选项分析 → 决策输出），思考文案由性格原型模板生成，不同性格的措辞、关注点、决策逻辑完全不同 |
| **文献性格原型** | 12 种原型取自出租车司机行为研究：Camerer(1997)、Farber(2005/2015)、Haggag & Paci(2014)、Wong(2001)、Tang(2017)、Szeto(2013)、Zhan(2016) 等。例如「收益猎手型」盯日收入目标、「价格敏感型」算每公里单价、「区域深耕型」拒绝离开自己的地盘 |
| **记忆模块** | 记录行驶轨迹、去过的区域及次数、收益流水、每一次派单决策及理由。接单距离按实际空驶滑动更新，聚类图随运营演化 |
| **偏好区域** | 每个司机的 `prefZones` 与性格设定呼应，车辆起始位置就在偏好区域内，地图轨迹用司机专属颜色区分 |
| **卡片交互** | 点击司机卡片展开：LLM 三段思考过程、记忆摘要、五维特质条、人物小传与文献依据；另有「查看当日行驶路径」按钮，在地图上绘制该司机当天轨迹 |
| **车队与订单** | 8 辆车 / 每批 2~3 单。接驾、载客中的车辆暂不可派；可用车辆不足时，订单进入待派队列 |

### 1.2 实时车速 · 需求热力 · LLM 接入（本轮新增）

| 能力 | 实现 |
| --- | --- |
| **实时车速** | 车速以高德 `AMap.Driving` 返回的 `distance / time` 为基准（该 ETA 已含实时路况），叠加 ±6% 波动与天气降速系数；地图车辆上方浮动 `xx km/h` 胶囊，司机卡片、派单面板同步显示，左侧接口面板给出车队均值与拥堵指数 |
| **分段路径规划** | 接单后从车辆当前位置规划到上车点，上车后规划到送达点。各路段先生成仿真路径；及时返回的高德规划用于推演，迟到的结果保留当前仿真路径 |
| **需求热力图** | 接入 `AMap.HeatMap`，权重 = 区域需求 + 供需缺口 + 车辆分布；图层开关独立控制，图例给出蓝→青→黄→红渐变。插件不可用时自动跳过，不影响其余图层 |
| **LLM 推理引擎** | 默认「本地链式推理」，离线可用；点「接入在线模型」可填 OpenAI 兼容接口（DeepSeek / 通义 / vLLM 等）、模型名与 Key，配置存 localStorage。派单后真实调用模型，以该司机的性格、偏好区域、今日收入为 system prompt 生成三段思考，失败自动回退并显示原因 |
| **LLM 运行指标** | 智能体页顶部状态栏实时统计推理调用数、成功数、平均延迟、累计 token；卡片内标注「在线模型思考 · 模型名 · 延迟 · token」 |
| **地图体验** | 车队 8 辆、内置示例 48 辆、车速标签按文字变化才刷新、热力数据 6 tick 更新一次，避免整层重建 |
| **司机详情弹层** | 在调度地图上点击任意车辆（或派单面板右上角「思考 · 记忆」）弹出该司机的详情：思考过程（链式三步 + 在线模型原文 + 思考历史）、记忆模块（轨迹点、今日去过、正在进行的行程、决策记忆、收入记忆）、性格设定（特质条、偏好区域、文献依据）。弹层每 1.6s 自刷新，保留当前 tab 与滚动位置 |

演示深链：`index.html?heat=1&mod=map` 打开热力图，`index.html?mod=agents&open=A03` 直达并展开某位司机，`index.html?drv=A03&dtab=memory` 直接打开某位司机的记忆页（`dtab` 可取 `think` / `memory` / `traits`）。

### 1.3 司机记忆模块

司机记忆是滑动窗口结构，`memory = { trajectory, visitedZones, decisions, earningsLog, thoughtHistory, dailyRoute, llm }`：

| 记忆 | 写入时机 | 容量 |
| --- | --- | --- |
| `trajectory` | 每 2 tick 记录一次经纬度与所在区域（`updateDriverMemory('move')`） | 最近 200 点 |
| `visitedZones` | 随轨迹写入，按区域名累计到访次数 | 不裁剪（最多 10 个区域） |
| `decisions` | 司机接受 / 拒绝派单时写入订单、决策与理由 | 最近 50 条 |
| `earningsLog` | 送达结算时写入时间、金额与区域 | 不裁剪 |
| `thoughtHistory` | 每次链式推理生成时写入三步思考 | 最近 20 条 |
| `dailyRoute` | 与轨迹同步写入，用于「查看当日行驶路径」 | 最近 300 点 |

仿真从 08:00 起跑，首次打开弹层若记忆为空会显得很空，因此启动时 `seedDriverMemory()` 按每位司机的偏好区域合成 07:00–08:00 的早班记忆（一段跨区巡游轨迹、到访区域、两单收入与两条决策），之后全部由仿真实时写入覆盖/追加。

## 二、仿真车队规模

| 项 | 值 |
| --- | --- |
| 在线车辆 | **8 辆**（`FLEET_SIZE`） |
| 生成方式 | 与 8 名司机智能体 **1:1 绑定**，号牌一一对应；每辆车起始位置取该司机的**偏好区域**，终点取其次偏好区域 |
| 路径形态 | 片区间折线 + 法向弯曲（`roadPath()`）；接单后按「当前位置 → 订单区域」重新规划，起终点重合时生成短巡游路径避免退化 |
| 状态分布 | 初始为空闲巡游，收到订单后依次接驾、载客、送达并恢复空闲 |
| 对应真实规模 | 郑州巡游车 11,875 台；此处为 **8 名代表性司机 Agent 的行为样本**，不追求统计抽样代表性 |

车队规模从数百辆缩减到 8 辆后，渲染策略随之调整：**每辆车独立绘制一条轨迹线，并用司机性格色区分**（不再按 OD 对去重），8 条彩色轨迹能直观看出每个司机的偏好活动范围。车辆 marker 选中时展开光晕，选车只改选中态、不重建整层。

**天气影响**：`WEATHER.impact` 同时作用于两处——恶劣天气按 0.68~0.90 系数降低车速（雨雪减速），并按影响系数抬升区域需求与订单收益（雨天打车需求上行）。

## 三、现实数据接口（高德开放平台）

页面左上角的「现实数据接口」面板会实时显示每类接口的接入状态：

| 接口 | 用途 | 降级策略 |
| --- | --- | --- |
| JS API 2.0 底图 | 郑州市真实地图底图 | 失败切换离线 SVG 示意底图 |
| TileLayer.Traffic | 实时路况图层，180s 自动刷新 | 关闭图层，不影响其余功能 |
| PlaceSearch | 10 个片区的真实坐标校准 | 未命中则沿用内置近似坐标 |
| Driving | 车辆 → 推荐区域的真实路径、距离、耗时 | 失败改用直线估算并标注"估算" |
| Weather | 郑州实时天气 → 需求影响系数 | 走 REST v3 兜底，再失败用内置「多云 24°」 |
| 车辆位置 | 无 GPS 数据，由规划路径插值推演 | 退回内置轨迹点插值 |

- POI 检索采用**串行 + 关键词兜底**（先用地标名，失败退回片区名），并对漏检片区**二次重试**，避免并发限流。
- **路径规划全量覆盖**：8 辆车规模下 `PLAN_MAX = FLEET_SIZE`，按 OD 对做一次轻量去重后几乎每辆车都能拿到一次独立的 `AMap.Driving` 真实路径，规划结果回填给该 OD 上的车辆。第一轮 170ms 间隔，第二轮只补失败的 OD 对、间隔放宽到 420ms。
- **派单即重规划**：司机接单后立刻以「当前位置 → 新目标」调用 `planRouteTo()` 重新导航，旧路径作废，车辆实时位置与车速都跟本次导航路线一致。
- **车辆位置推演**：`v.realPath` 存高德返回的 `[lng,lat]` 路径点，`posAt()` 按进度 `v.t` 在该折线上线性插值得到当前坐标。有真实路径时优先用真实路径，没有则退回内置轨迹。面板显示「路径推演 N/12」。
- 真实规划路线在地图上以**司机性格色**绘制，选中车辆线宽加粗、透明度提高；每 2 tick 把当前位置写入该司机的记忆轨迹，供「当日行驶路径」回放。
- Key 与安全密钥写在 `index.html` 顶部（`window._AMapSecurityConfig` + SDK 的 `key` 参数）。

## 五、逐车轨迹导入与回放

地图模块左上角「历史轨迹数据」提供两个入口：**加载内置示例**、**导入 CSV / JSON**。数据加载后，地图底部出现回放条（播放/暂停、进度拖动、0.5×~4× 倍速、重置）。

### 5.1 输入格式

**CSV / TSV**（表头自动识别，UTF-8）：

```csv
plate,time,lng,lat
豫A·T0231,2024-01-15 08:00:00,113.627000,34.748000
豫A·T0231,2024-01-15 08:01:30,113.644000,34.746500
```

| 字段 | 可接受的列名（任一） | 说明 |
| --- | --- | --- |
| 车辆标识 | 车牌 / plate / taxi_id / id / car_id / device | 必填 |
| 时间戳 | 时间 / time / ts / timestamp / datetime / gps_time | 必填，支持 `YYYY-MM-DD HH:mm:ss`、`HH:mm:ss`、10/13/16~19 位时间戳 |
| 经度 | 经度 / lng / lon / longitude / x | 必填 |
| 纬度 | 纬度 / lat / latitude / y | 必填 |
| 速度 | 速度 / speed | 可选 |

无表头时按「车牌, 时间, 经度, 纬度[, 速度]」固定列序解析；分隔符自动识别 `,` / `\t` / `;`。

**JSON** 支持两种形态：

```json
{"tracks": [{"id": "豫A·T0231", "points": [[113.627, 34.748, "2024-01-15 08:00:00"], ...]}]}
```

```json
[{"id": "豫A·T0231", "t": 1705305600, "lng": 113.627, "lat": 34.748}, ...]
```

### 5.2 解析与回放规则

- **坐标校验**：经度 72~136、纬度 3~54（中国境内），越界记录计入「丢弃记录」。
- **规模上限**：最多保留 160 辆车，单车最多 600 个定位点（超出按等距抽稀），避免渲染爆掉。
- **时间轴**：全数据集取 `[t0, t1]`，按 120ms 一步推进；1× 时整段约 60 秒播完。
- **插值**：相邻定位点之间按时间戳线性插值。两次行程之间的等客区间表现为**原地停留**——内置示例正是这样生成的。
- **显隐**：早于车辆首个点或晚于末个点的时刻，该车 marker 隐藏，不会堆在终点。
- **视觉区分**：历史轨迹车辆画成**小方块**（`#0284c7`），仿真车辆是**圆点**；历史路线为淡青色铺底，可在「图层」里用「历史轨迹」开关整体隐藏。
- 轨迹可同时在地图模块和离线 SVG 底图（高德不可用时）上回放。

### 5.3 内置示例

没有真实郑州逐车 GPS 数据可用，内置示例按**郑州 10 个片区的 OD 结构 + 时段强度曲线**合成 48 辆车、约 6 小时、约 5 千个定位点（数量已下调，避免与仿真车队抢视线）：

- 等客时长随时段变化（高峰 3~6 min，平峰 8~15 min），行驶速度高峰更慢（约 16~26 km/h）；
- 行程距离 2.2~10.7 km，路径带法向弯曲，形态接近沿路网绕行；
- 用固定随机种子生成，每次加载结果一致。

示例仅用于演示**导入与回放流程**，不是真实运营数据。点「下载示例 CSV」可把当前数据集导出成 CSV，再用「导入 CSV/JSON」导回来，形成完整的往返验证。

### 5.4 车辆显示三档

地图左上角「车辆显示」提供三档一键切换，避免两类车辆叠在一起互相干扰：

| 档位 | 显示内容 | 联动 |
| --- | --- | --- |
| **全部** | 模拟车辆 + 历史车辆 | 图层全部打开 |
| **仅模拟**（● 圆点） | 8 辆司机智能体车队 + 调度轨迹 | 历史轨迹层关闭 |
| **仅历史**（■ 方块） | 导入的逐车轨迹 + 轨迹线 | 模拟车辆与调度轨迹层关闭；历史路线自动加深（opacity 0.13 → 0.30），因为不再有仿真车抢视线 |

- 三档与下方「图层」chip 双向同步：手工关掉「模拟车辆」chip，档位会自动跳到「仅历史」；两个都关则显示为无高亮（自定义态）。
- 选中车辆的高亮路线跟随「模拟车辆」层，切到「仅历史」时一并隐藏。
- 选「仅历史」但还没导入数据时，会**自动加载内置示例**并给出事件提示，不会出现"点了没反应"。
- 新导入的数据集默认把历史层打开，避免用户以为导入失败。
- 这套逻辑在离线 SVG 底图（高德不可用）下同样生效。

## 六、数据标定（双层）

郑州本地有官方公开的**规模与运营指标**，但没有公开的**逐笔行程 / 分时订单**数据。
因此采用双层标定：**水平（车辆数、单量、客单价）取自郑州官方数据，形状（时段曲线、距离与速度分布）取自开源逐笔行程记录。**

### 6.1 郑州本地官方数据（定水平）

来源：郑州市交通运输局政务公开答复、《郑州市网约车市场经营风险提示》各期。

| 项 | 值 |
| --- | --- |
| 巡游出租车 | **11,875 台**，46 家公司 + 5 个个体联队，驾驶员约 2 万人 |

### 6.3 清洗规则

剔除时长 < 1 min 或 > 3 h、里程 ≤ 0 或 > 100 mile、车费 ≤ 0、总额 ≤ 0、载客数不在 1~6、
平均速度不在 1~110 km/h 的记录。里程按 `1 mile = 1.609344 km` 换算。

## 七、司机智能体聚类

8 个司机 Agent 以 `[收益敏感度, 接受阈值, 平均接单距离]` 三维特征标准化后做 **K-Means（k=3，最远点初始化 + Lloyd 迭代）**，结果在「司机智能体」模块以散点图呈现。初始接单距离按性格原型设定，派单后按实际空驶距离滑动更新：

- 横轴 = 收益敏感度，纵轴 = 平均接单距离，颜色 = 聚类簇，菱形 = 簇心，虚线椭圆 = 簇分布范围（协方差主轴 1.75σ）。
- 聚类簇按语义动态命名：**远距高收益派**、**近场保守派**、**均衡通勤派**，成员由 K-Means 实时计算（不再写死），每个簇给出对应的派单策略建议。
- 点击散点或右侧簇卡片：其余簇淡出、该簇高亮、簇名药丸浮现，同时上方对应的司机卡片加描边联动。

## 八、决策图谱交互

- 点击任意节点：右侧显示阶段、职责、输入、输出、运行指标、上下游跳转。
- `协作链高亮`：按 900ms 步进依次点亮智能体及其内部步骤。
- `重放本轮协作`：从 A0/A1 开始快速重放一遍。
- `只看主链路`：弱化非主链节点，突出协作主干。
- 地图面板点「查看决策图谱」会直接定位到 A3 调度派单智能体。

## 九、数据说明

- 订单、车辆、收益等**仿真数据为模拟值**，不含真实个人信息或运营数据。
- 区域名称与坐标优先使用高德 POI 检索结果，失败时使用郑州市主城区近似坐标（GCJ-02）。
- 车辆位置为**路径推演值**，不是真实 GPS 定位，页面已显式标注。
- 行业规模与运营指标来自郑州市交通运输局公开数据；时段与分布特征来自 NYC TLC 公开数据（Public Domain），只取分布、不含乘客身份信息，也不复现个体轨迹。
- 「内置示例」轨迹为**按郑州路网与时段特征合成的演示数据**，不是真实车辆轨迹；导入自有数据时请确保来源合规。
- 指标数值为演示用示意值，不代表实测结果；申报材料中已注明"以最终实验结果为准"。

## 十、与主项目的关系

本目录是可独立运行的**前端可视化原型**（单文件、无后端依赖）。
主项目（`../src`、`../web`、`../server.py`）中的 Python 仿真环境与调度 Agent 作为正式实现，
后续可将本页面的 `VEHICLES` / `ZONES` / 事件流替换为后端状态接口的返回值；
`applyHist()` 也可直接接后端返回的轨迹 JSON，无需改动回放层。
