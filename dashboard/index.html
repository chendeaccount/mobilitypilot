实验结论

指标以最终实验结果为准
  • 多智能体协同相较需求热点推荐，订单完成率提升约 6.8 个百分点，主要来自对"多车同向聚集"的抑制。
  • 引入司机 Agent 的差异化响应后，空驶距离下降明显，但收益公平性（基尼系数）需在推荐权重中显式约束。
  • 当推荐接受率低于 45% 时，闭环反馈的收益开始收敛；此时应降低单轮推荐强度，避免震荡。
  • 指标以仿真实验为准，不预设真实场景的提升幅度，后续接入公开出行数据后重新标定。

MobilityPilot：面向城市出行的多智能体协同决策与动态调度系统

面向郑州市出租车运营场景，构建"环境感知 → 智能推荐 → 行为响应 → 反馈优化"的闭环调度机制。系统由天气环境、态势感知、路径规划、调度派单、司机执行五个智能体接力完成一次调度，接入高德开放平台的 POI 检索、实时路径规划与路况数据，在动态供需下为空闲车辆推荐候客区域，并抑制多车同向聚集造成的局部运力浪费。

五个智能体

决策链
  • A0 天气环境智能体：取郑州实时天气，换算需求影响系数，作为环境输入修正 A1 需求与 A2 的 ETA。
  • A1 态势感知智能体：融合高德 POI 热度、实时路况、车辆 GPS 与订单流，输出区域供需缺口。
  • A2 路径规划智能体：调用高德 Driving 接口做真实路网规划，输出距离、ETA 与空驶成本。
  • A3 调度派单智能体：综合评分并做车辆-订单匹配，向司机下发派单指令与推荐路线。
  • A4 司机执行智能体：代表司机与车辆确认接单，沿规划路线行驶、送达并结算。每个司机均接入 LLM 链式思考引擎（态势评估→选项分析→决策输出），具备独立思考、记忆模块与性格原型。
  • A1 → A2 → A3 → A4 首尾相接形成闭环：执行结果回写为区域权重与司机阈值，供下一轮 A1 / A3 使用。
  • 8 名司机智能体：基于出租车行为研究文献（Camerer、Farber、Haggag、Tang 等），赋予差异化性格原型（收益猎手、价格敏感、区域深耕、保守观望等），每人均有偏好区域、记忆模块与独立 LLM 思考过程。点击司机卡片可查看完整链式推理。

系统模块

  • 态势总览：订单完成率、等待时间、空驶率、司机收益与区域供需缺口的实时监控。
  • 城市调度地图：郑州市主城区地图，展示区域需求强度、车辆分布与调度轨迹回放，并标注高德接口的实时接入状态。
  • 决策图谱：以有向图呈现 5 个智能体的接力协作与各自内部步骤，支持节点下钻查看输入、输出与指标。
  • 历史数据标定：郑州本地官方口径数据定规模水平，开源逐笔行程数据定时段形状，双层标定后实时驱动仿真参数。
  • 司机智能体：不同收益偏好与接受阈值的司机 Agent 群体及其行为日志。
  • 对比实验：随机调度 / 热点推荐 / 无反馈调度 / 多智能体协同四组策略的指标对比。

技术路线

  • 仿真环境：Python 构建订单生成、车辆移动、供需状态更新与路网成本计算。
  • 现实数据接口：高德 JS API 2.0 —— PlaceSearch 校准片区坐标、Driving 做真实路径规划、TileLayer.Traffic 提供实时路况。
  • 调度 Agent：基于 Qwen 等开源大模型，结合工具调用与结构化决策输出。
  • 工具层：需求预测、路径成本（高德 ETA）、收益评估三类可调用工具。
  • 司机 Agent：以收益敏感度、区域偏好、接受阈值刻画差异化响应。
  • 双层数据标定：郑州巡游车 11,875 台、年客运量 2.9 亿人次、网约车三期运营指标来自市交通运输局公开数据，用于定规模水平；时段强度、行程距离与速度分布来自 NYC TLC 逐笔行程记录（2024-01，271 万条），用于定形状。
  • 可视化：本页面为交互式原型，地图与图谱共享同一份仿真状态。

创新点

  • 从静态推荐到闭环决策：把"推荐对司机行为与后续供需的影响"纳入决策依据。
  • 多智能体行为交互：探索个体最优与系统整体效率之间的张力。
  • 大模型推理 + 交通仿真：形成可交互、可验证、可解释的实验平台。

数据与合规

  • 行业规模与运营指标来自郑州市交通运输局政务公开答复与《郑州市网约车市场经营风险提示》（2024-05、2025-04、2026-06 三期），均为官方公开口径。
  • 郑州未公开逐笔行程与分时订单数据，因此时段形状、行程距离与速度分布改用 NYC TLC Yellow Taxi Trip Records（2024 年 1 月，Public Domain）标定，形成「郑州定水平、开源定形状」的双层标定。
  • NYC TLC 数据为纽约市公开发布的行程记录，不含乘客身份信息；仅取其分布特征，不做个体轨迹复现。
  • 车辆位置、订单与收益等运行态数据为仿真生成，不含任何真实个人信息与轨迹。
  • 地图底图、路径规划与路况数据来自高德开放平台，符合国内地图数据合规要求。
  • 高德 Key 与安全密钥由团队自行申请，当前仅用于原型演示；正式部署将配置域名白名单，服务类请求由后端代理，避免前端明文暴露。
  • 区域划分与坐标均为郑州市主城区近似位置，仅用于演示。
  • 后续如接入真实运营数据，将进行脱敏处理并遵循个人信息保护相关要求。
